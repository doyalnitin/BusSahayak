PART 1: Train VOSK (Speech-to-Text)
Teach VOSK your Hindi bus commands
What is VOSK Training?
Under the Hood
VOSK uses Kaldi under the hood — the industry-standard open-source speech recognition toolkit used by researchers worldwide.
What Training Does
Training means teaching it YOUR specific vocabulary (Hindi bus commands). Pre-trained model understands general Hindi, but not bus-specific terms.
Goal
A model that accurately recognizes words like "Delhi se Jaipur", "window seat", "kitne baje" — bus-specific Hindi.
How VOSK Training Works
Raw Audio
Record 100+ Hindi bus commands as WAV files (16kHz, mono)
Transcripts
Create text transcripts for each audio file: utt001 delhi se jaipur jana hai
Vocabulary + Language Model
Build vocab list + FST language model from text corpus
Train Acoustic Model
Kaldi s5 recipe trains the acoustic model on your data
Export to VOSK Format
Convert Kaldi model → VOSK format for real-time inference

Step 2: Create Training Data

Record 100+ Hindi bus commands as WAV files and create text transcripts for each.

Audio Requirements
Format: WAV, Sample Rate: 16kHz, Channels: Mono (16-bit PCM). Use Audacity or any phone recorder app.

Transcript Format: utt_id transcript

transcripts.txt
utt001 delhi se jaipur jana hai utt002 window seat chahiye utt003 kitne baje ki bus hai utt004 ac volvo book karni hai utt005 mera ticket cancel karo utt006 bus kahan hai abhi utt007 payment upi se karunga utt008 lower deck seat do utt009 kal subah ki bus chahiye utt010 refund kab milega
Recording Tips
• Speak naturally, like you're talking to a friend
• Vary your tone and speed
• Record in a quiet room (minimal background noise)
• Each command: 2-5 seconds duration
What to Record
• Bus search commands (city, date, time)
• Seat preference (window, upper, lower)
• Payment related (UPI, card, cash)
• Status queries (bus location, ETA)
• Cancellation & refund requests
Step 3: Create Vocabulary

List all unique words from your transcripts. This is the vocabulary VOSK will recognize.

vocab.txt
<SPK> delhi se jaipur jana hai window seat chahiye kitne baje ki bus ac volvo book karni mera ticket cancel karo kahan abhi payment upi karunga lower deck kal subah refund kab milega rupaye hain
Vocab Size
Aim for 200-500 unique words. Too few = poor recognition. Too many = slower performance. Bus domain is narrow enough to keep it manageable.
Step 4: Create Language Model

Use SRILM or OpenGrm to create an FST language model from your text corpus.

bash — SRILM
# Install SRILM brew install srilm # Mac sudo apt-get install srilm # Linux # Create n-gram counts ngram-count -text corpus.txt -order 3 -write vocab.count # Build language model (ARPA format) ngram-count -text corpus.txt -order 3 -vocab vocab.txt \ -lm lang.arpa # Convert to FST format for Kaldi arpa2fst --disambig-symbol=0 \ --read-symbol-table=words.txt \ lang.arpa graph/LG.fst
bash — OpenGrm (Alternative)
# Install OpenGrm brew install opengrm-ngram # Mac # Build language model ngramcount -o 3 corpus.txt corpus.cnt ngrammake corpus.cnt lang.fst

PART 2: Train Gemma (LLM)
Fine-tune Gemma on Hindi bus conversations
What is Gemma Fine-tuning?
Pre-trained Gemma
Gemma is pre-trained on general internet text. It knows a lot about everything, but nothing specific about bus booking.
Fine-tuning
Fine-tuning teaches it YOUR specific conversations (Hindi bus booking). It learns the patterns, responses, and context of your domain.
LoRA
Uses LoRA (Low-Rank Adaptation) — only trains a small adapter (~50MB), not the whole model (~2GB). Saves time, memory, and disk space.
How Gemma Fine-tuning Works
Training Dataset (JSONL)
200+ Hindi bus conversation pairs: {"instruction": "Delhi se Jaipur", "response": "Kab jana hai?"}
Gemma 2B (4-bit Quantized)
Load pre-trained model with BitsAndBytes 4-bit quantization — fits in 6GB VRAM
LoRA Adapter
Attach trainable LoRA layers to attention projections — only ~50MB of trainable params
Train (3 epochs)
SFTTrainer fine-tunes on bus conversations — 1-2 hours on T4 GPU
Export to GGUF → Ollama
Merge LoRA → Convert to GGUF (Q4_0) → Import into Ollama for local inference

Step 3: Load Gemma Model (4-bit Quantized)
python
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig import torch # 4-bit quantization config — reduces model from ~5GB to ~1.5GB bnb_config = BitsAndBytesConfig( load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_compute_dtype=torch.float16, bnb_4bit_use_double_quant=True ) # Load Gemma 2B with quantization model = AutoModelForCausalLM.from_pretrained( "google/gemma-2b-it", quantization_config=bnb_config, device_map="auto" ) tokenizer = AutoTokenizer.from_pretrained("google/gemma-2b-it") tokenizer.pad_token = tokenizer.eos_token # Verify it loaded print(f"Model loaded: {model.num_parameters()/1e9:.1f}B params") print(f"Memory: {torch.cuda.memory_allocated()/1e9:.2f}GB")
Memory Requirements
Gemma 2B (4-bit): ~1.5GB VRAM
Gemma 2B (full): ~5GB VRAM
With LoRA training: ~4GB VRAM
Fits on T4 GPU (16GB) easily
Access Required

Step 4: Configure LoRA
python
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training # Prepare model for k-bit training (required for 4-bit models) model = prepare_model_for_kbit_training(model) # LoRA configuration lora_config = LoraConfig( r=16, # Rank — higher = more capacity, more VRAM lora_alpha=32, # Scaling factor target_modules=[ "q_proj", # Query projection "k_proj", # Key projection "v_proj", # Value projection "o_proj" # Output projection ], lora_dropout=0.05, # Dropout for regularization bias="none", task_type="CAUSAL_LM" ) # Apply LoRA to model model = get_peft_model(model, lora_config) # Check trainable parameters model.print_trainable_parameters() # Output: trainable params: 4,718,592 || all params: 2,507,599,872 || 0.19%
Why LoRA?
Full fine-tuning of Gemma 2B would require ~8GB VRAM and hours of training. LoRA trains only 0.19% of parameters (~4.7M), reducing VRAM to ~4GB and training time to ~1 hour. The adapter weights are only ~20MB.
Step 5: Train the Model
python
from trl import SFTTrainer from transformers import TrainingArguments from datasets import load_dataset # Load dataset dataset = load_dataset("json", data_files="bus_conversations.jsonl", split="train") # Training arguments training_args = TrainingArguments( output_dir="./gemma-bus-sahayak", num_train_epochs=3, per_device_train_batch_size=4, gradient_accumulation_steps=4, learning_rate=2e-4, fp16=True, save_steps=100, logging_steps=10, max_grad_norm=0.3, warmup_ratio=0.03, optim="paged_adamw_8bit", report_to="none" ) # SFTTrainer — Supervised Fine-Tuning Trainer trainer = SFTTrainer( model=model, train_dataset=dataset, args=training_args, dataset_text_field="text", max_seq_length=512, packing=True # Packs short examples together — 2x faster training ) # Start training! trainer.train() # Training time: ~1-2 hours on T4 GPU # Loss should decrease from ~2.5 to ~0.8

PART 3: Train Piper (TTS)
Teach Piper to speak in your voice
What is Piper Training?
Under the Hood
Piper uses VITS (Variational Inference with adversarial learning for end-to-end Text-to-Speech) — state-of-the-art neural TTS.
What Training Does
Training means teaching it to speak in YOUR voice. You record 50-100 sentences, and the model learns your voice characteristics.
Why Piper?
Ultra-fast inference (~50ms per sentence), runs on CPU, produces natural-sounding Hindi speech. Perfect for offline voice assistants.
How Piper Training Works
Record Voice (50-100 sentences)
WAV format, 22050Hz mono, each sentence 3-10 seconds. Clear audio, no background noise.
Create Metadata (metadata.csv)
Map each audio file to its transcript: recording_001|Namaste, main aapka voice assistant hoon.
Configure Training (config.json)
Set language (hi), sample rate, model architecture, and character set
Train VITS Model
Coqui TTS trainer — 1-4 hours on T4 GPU depending on data size
Export to ONNX → Piper
Convert to ONNX format for ultra-fast CPU inference (~50ms per sentence)

PART 6: Common Issues & Fixes
Troubleshooting guide for all three models
VOSK Issues
Issue Cause Fix
Training fails Wrong audio format Check audio is WAV, 16kHz, mono, 16-bit PCM. Use: sox input.wav -r 16000 -c 1 -b 16 output.wav
Poor recognition accuracy Too few training samples Record 200+ utterances. Include variations in tone, speed, and accent.
Model doesn't recognize bus terms Words missing from vocabulary Add all bus-specific words to vocab.txt and rebuild language model.
Kaldi build fails Missing dependencies Install sox, libatlas-base-dev (Linux), gfortran. Check Kaldi docs for your OS.
Gemma Issues
Issue Cause Fix
Out of Memory (OOM) Batch size too large Reduce per_device_train_batch_size to 2 or 1. Increase gradient_accumulation_steps to compensate.
Model produces gibberish Learning rate too high or bad data Lower LR to 1e-4. Check dataset for formatting errors. Ensure proper JSONL structure.
Model doesn't speak Hindi Dataset too small or English-heavy Add 200+ Hindi examples. Ensure 90%+ of training data is in Hindi/Hinglish.
GGUF conversion fails Wrong merge order First merge LoRA adapter with base model, then convert merged model to GGUF. Don't convert adapter directly.
HuggingFace access denied Didn't accept Gemma license Go to huggingface.co/google/gemma-2b-it, accept license agreement, then huggingface-cli login.
Piper Issues
Issue Cause Fix
Output sounds robotic Not enough training data Record 100+ sentences. Vary speaking style, tone, and speed. More data = more natural.
Hindi pronunciation wrong Character set misconfigured Ensure config.json has correct character set for Hindi. Include Devanagari characters if needed.
Training doesn't converge Dataset too small or inconsistent Ensure consistent recording quality. Remove noisy samples. Aim for 50+ clean recordings minimum.
ONNX export fails Incompatible model architecture Use XTTS v2 or VITS model. Export with TTS.utils.export_onnx. Check Coqui TTS docs.
Model too slow Running on GPU instead of CPU Piper ONNX is optimized for CPU. Use piper --model my_voice.onnx directly — it's fastest on CPU.
