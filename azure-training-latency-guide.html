1.4 Audio Conversion Commands
# Convert M4A to WAV (16kHz, Mono, 16-bit) for STT ffmpeg -i input.m4a -ar 16000 -ac 1 -sample_fmt s16 output_stt.wav # Convert M4A to WAV (48kHz, Mono, 16-bit) for TTS ffmpeg -i input.m4a -ar 48000 -ac 1 -sample_fmt s16 output_tts.wav # Batch convert all M4A files for f in *.m4a; do ffmpeg -i "$f" -ar 16000 -ac 1 -sample_fmt s16 "${f%.m4a}_stt.wav" ffmpeg -i "$f" -ar 48000 -ac 1 -sample_fmt s16 "${f%.m4a}_tts.wav" done # Verify audio properties ffprobe -v error -show_entries stream=sample_rate,channels,bits_per_sample output.wav

4. LATENCY OPTIMIZATION STRATEGIES
4.1 Six Core Strategies
1. Quantized Models (Q4)
Compress model weights from 32-bit to 4-bit integers.
Reduces model size by 75%, inference 50% faster.
Tool: llama.cpp, GPTQ, AWQ
Impact: Gemma 2B from 2GB to 500MB
50% faster
2. GPU Acceleration
Use CUDA/TensorRT for parallel matrix operations.
10x faster than CPU for transformer inference.
Tool: NVIDIA TensorRT, ONNX Runtime GPU
Impact: 150ms to 15ms on GPU
10x faster
3. Model Caching
Keep loaded models in GPU/CPU memory between requests.
Eliminates model loading overhead (2-5 seconds).
Tool: TorchServe, TensorRT-LLM
Impact: Cold start 3s to warm 0ms
80% faster
4. Streaming (TTS)
Generate and play audio simultaneously.
User perceives near-instant response.
Tool: Piper streaming, Bark streaming
Impact: Perceived latency 0ms
Perceived 0ms
5. Parallel Processing
Run STT and audio preprocessing concurrently.
Pipeline LLM and TTS stages.
Tool: Python asyncio, threading
Impact: Overlap STT+LLM phases
50% faster
6. Edge Deployment
Run models on-device (phone/tablet).
Zero network latency, works offline.
Tool: ONNX Runtime Mobile, TFLite
Impact: 30% faster on-device
30% faster

5. AZURE COMPLETE FLOW - Deploy and Integrate
5.1 Complete Request Flow
Step 1: User Speaks
Blind user holds screen - Microphone activates - Records 16kHz PCM audio - Sends to FastAPI backend via HTTPS
Step 2: Audio to Vosk STT (50ms)
FastAPI receives audio - Sends to local Vosk server (16kHz WAV) - Custom model transcribes - Returns Hindi/English text
Step 3: Text to Gemma 2B LLM (150ms)
FastAPI sends text to local Gemma 2B Q4 (llama.cpp) - Processes intent - Generates response in same language - Returns text
Step 4: Response to Piper TTS (50ms)
FastAPI sends response text to local Piper TTS - Generates 24kHz PCM audio - Returns audio stream
Step 5: Audio to User
FastAPI returns audio to React Native app - Speaker plays response - Haptic vibration confirms - Total latency: 250ms

5.3 FastAPI Application Code
# main.py - FastAPI with Vosk + Gemma 2B + Piper from fastapi import FastAPI, UploadFile, File from fastapi.responses import JSONResponse import vosk, json, time, torch from llama_cpp import Llama from piper import PiperVoice app = FastAPI(title="BusSahayak Voice API") # Load models once at startup (caching) stt_model = vosk.Model("vosk-model-hi-0.22") stt_recognizer = vosk.KaldiRecognizer(stt_model, 16000) llm = Llama(model_path="gemma-2b-Q4_K_M.gguf", n_ctx=2048) tts = PiperVoice.load("hi_IN-piper.onnx") @app.post("/voice") async def process_voice(audio: UploadFile = File(...)): start = time.time() audio_data = await audio.read() # STT: Vosk (50ms) stt_recognizer.AcceptWaveform(audio_data) user_text = json.loads(stt_recognizer.Result())["text"] # LLM: Gemma 2B Q4 (150ms) response = llm(f"BusSahayak: {user_text}", max_tokens=50) response_text = response["choices"][0]["text"].strip() # TTS: Piper (50ms) audio_buffer = io.BytesIO() tts.synthesize(response_text, audio_buffer) latency = int((time.time() - start) * 1000) return JSONResponse({ "user_text": user_text, "response_text": response_text, "latency_ms": latency, "audio_base64": base64.b64encode(audio_buffer.getvalue()).decode() })
