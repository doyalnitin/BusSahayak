2. Fine-Tune Gemma for Hindi Bus Booking
LoRA / QLoRA fine-tuning using Hugging Face transformers on Azure ML
Gemma 2 2B LoRA r=16 QLoRA 4-bit Azure ML GPU
Why LoRA / QLoRA?
Low Rank Adaptation
Freeze 99% of model weights. Train only 0.1% adapter layers. Reduces VRAM from 24GB to 6GB.
QLoRA 4-bit
Quantize base model to 4-bit NF4. Only LoRA adapters in FP16. Fits in a single T4 GPU (16GB).
Fast Training
Train 500+ examples in ~15 min on Azure NC6 (1x K80). Cost: under $2 on free tier.
Step 1: Pull Base Model
Download google/gemma-2-2b from Hugging Face Hub. Accept Google's license on HF first.
Step 2: Prepare Dataset
Create JSONL training data with Hindi bus booking conversations. Format: {"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
Step 3: Configure LoRA
Set LoRA config: r=16, lora_alpha=32, target_modules=["q_proj","v_proj","k_proj","o_proj"]
Step 4: Train on Azure ML
Submit training job to Azure ML compute cluster. Monitor via ML Studio dashboard.
Step 5: Export to Ollama
Merge LoRA adapters, convert to GGUF, create Modelfile, then ollama create.

3. Full Python Training Script
QLoRA fine-tuning for Gemma 2 on Azure ML
requirements.txt
transformers==4.44.0 peft==0.12.0 trl==0.9.4 datasets==2.21.0 accelerate==0.33.0 bitsandbytes==0.43.1 torch==2.4.0 optimum==1.21.0 sentencepiece==0.2.0 protobuf==5.27.0 huggingface_hub==0.24.0
train.py — QLoRA Fine-Tuning Script
# train.py - BusSahayak Gemma 2 QLoRA Fine-Tuning # Run on Azure ML GPU compute (NC6 / T4) import os import json import torch from datasets import load_dataset from transformers import ( AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig, TrainingArguments, ) from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training from trl import SFTTrainer # ── Config ── MODEL_NAME = "google/gemma-2-2b" OUTPUT_DIR = "./gemma-bus-sahayak" DATASET_PATH = "./bus_booking_hindi.jsonl" MAX_SEQ_LENGTH = 512 NUM_EPOCHS = 3 BATCH_SIZE = 4 GRAD_ACCUM = 2 LEARNING_RATE = 2e-4 # ── 4-bit Quantization Config (QLoRA) ── bnb_config = BitsAndBytesConfig( load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_compute_dtype=torch.float16, bnb_4bit_use_double_quant=True, ) # ── Load Model + Tokenizer ── print("Loading Gemma 2 2B with 4-bit quantization...") tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME) tokenizer.pad_token = tokenizer.eos_token tokenizer.padding_side = "right" model = AutoModelForCausalLM.from_pretrained( MODEL_NAME, quantization_config=bnb_config, device_map="auto", trust_remote_code=True, ) model = prepare_model_for_kbit_training(model) # ── LoRA Config ── lora_config = LoraConfig( r=16, lora_alpha=32, target_modules=["q_proj", "v_proj", "k_proj", "o_proj", "gate_proj", "up_proj", "down_proj"], lora_dropout=0.05, bias="none", task_type="CAUSAL_LM", ) model = get_peft_model(model, lora_config) model.print_trainable_parameters() # ── Load Dataset ── print("Loading Hindi bus booking dataset...") dataset = load_dataset("json", data_files=DATASET_PATH, split="train") def format_prompt(example): msgs = example["messages"] text = "" for msg in msgs: if msg["role"] == "user": text += f"<start_of_turn>user\n{msg['content']}<end_of_turn>\n" else: text += f"<start_of_turn>model\n{msg['content']}<end_of_turn>\n" return {"text": text} dataset = dataset.map(format_prompt) # ── Training Args ── training_args = TrainingArguments( output_dir=OUTPUT_DIR, num_train_epochs=NUM_EPOCHS, per_device_train_batch_size=BATCH_SIZE, gradient_accumulation_steps=GRAD_ACCUM, learning_rate=LEARNING_RATE, warmup_ratio=0.1, weight_decay=0.01, logging_steps=10, save_strategy="epoch", fp16=True, report_to="none", optim="paged_adamw_8bit", lr_scheduler_type="cosine", ) # ── Trainer ── trainer = SFTTrainer( model=model, train_dataset=dataset, tokenizer=tokenizer, args=training_args, dataset_text_field="text", max_seq_length=MAX_SEQ_LENGTH, packing=True, ) # ── Train ── print("Starting QLoRA training...") trainer.train() # ── Save LoRA Adapters ── trainer.save_model(OUTPUT_DIR) tokenizer.save_pretrained(OUTPUT_DIR) print(f"Model saved to {OUTPUT_DIR}")

5. Export Fine-Tuned Model to Ollama Format
Merge LoRA, convert to GGUF, create Ollama model
Export Pipeline
# export_to_ollama.py — Merge LoRA + Convert to Ollama import torch from transformers import AutoModelForCausalLM, AutoTokenizer from peft import PeftModel # ── Step 1: Merge LoRA Adapters ── print("Loading base model...") base_model = AutoModelForCausalLM.from_pretrained( "google/gemma-2-2b", torch_dtype=torch.float16, device_map="cpu", ) print("Loading LoRA adapters...") model = PeftModel.from_pretrained(base_model, "./gemma-bus-sahayak") print("Merging adapters...") model = model.merge_and_unload() print("Saving merged model...") model.save_pretrained("./gemma-bus-sahayak-merged") AutoTokenizer.from_pretrained( "google/gemma-2-2b" ).save_pretrained("./gemma-bus-sahayak-merged") print("Merged model saved!")
Convert to GGUF + Create Ollama Model
#!/bin/bash # convert_and_create_ollama.sh # ── Step 2: Install llama.cpp converter ── git clone https://github.com/ggerganov/llama.cpp.git cd llama.cpp pip install -r requirements/requirements-convert_hf_to_gguf.txt # ── Step 3: Convert to GGUF ── python convert_hf_to_gguf.py \ ../gemma-bus-sahayak-merged \ --outfile ../bus-sahayak-q4_k_m.gguf \ --outtype q4_k_m # ── Step 4: Create Modelfile ── cat > ../Modelfile << 'EOF' FROM ./bus-sahayak-q4_k_m.gguf TEMPLATE """<start_of_turn>user {{ .System }} {{ .Input }}<end_of_turn> <start_of_turn>model """ SYSTEM """आप BusSahayak हैं — एक Hindi bus booking voice assistant। आप बस खोजने, बुक करने, स्टेटस चेक करने, और यात्रा संबंधी सवालों के जवाब देने में माहिर हैं। हमेशा Hindi में जवाब दें।""" PARAMETER temperature 0.7 PARAMETER top_p 0.9 PARAMETER top_k 40 PARAMETER max_new_tokens 256 EOF # ── Step 5: Create Ollama Model ── ollama create bus-sahayak -f ../Modelfile # ── Step 6: Test ── ollama run bus-sahayak "दिल्ली से जयपुर बस बताओ" echo "BusSahayak Ollama model ready!"

10. Troubleshooting
Common issues and their fixes
CUDA Out of Memory during training

Cause: Batch size too large for GPU VRAM.

Fix:

1. Reduce BATCH_SIZE from 4 to 1

2. Increase GRAD_ACCUM from 2 to 8 (same effective batch)

3. Reduce MAX_SEQ_LENGTH from 512 to 256

4. Enable gradient checkpointing: model.gradient_checkpointing_enable()

5. Use NC6 with 12GB VRAM, or NC12 with 24GB for larger models.

Gemma model requires HuggingFace license acceptance

Cause: Gemma is a gated model on HuggingFace.

Fix:

1. Go to https://huggingface.co/google/gemma-2-2b

2. Accept Google's license terms

3. Login: huggingface-cli login

4. Use your HF token in Azure ML environment variables

Azure ML job stuck in "Queued"

Cause: Compute cluster scaling up or quota exceeded.

Fix:

1. Check quota: az ml compute list-sizes -o table

2. Request GPU quota increase via Azure Portal

3. Try a different region (eastus, westus2, westeurope)

4. Use smaller VM size if NC6 quota is exhausted

Ollama slow inference on GPU VM

Cause: CUDA not properly installed or Ollama using CPU.

Fix:

1. Verify GPU: nvidia-smi should show K80

2. Check Ollama logs: ollama serve should mention CUDA

3. Reinstall CUDA toolkit: sudo apt install cuda-toolkit-12-1

4. Restart Ollama: pkill ollama && ollama serve &

5. Use quantized models (Q4_K_M) for faster inference

Azure Custom Speech poor accuracy

Cause: Insufficient training data or wrong audio format.

Fix:

1. Need 100+ audio samples minimum (500+ recommended)

2. Audio must be 16kHz WAV format

3. Add bus-specific vocabulary: बस, टिकट, बुकिंग, रद्द, रिफंड

4. Include diverse accents and background noise in training data

5. Re-train model after adding more data

Azure free credits exhausted early

Cause: Running expensive VMs without monitoring.

Fix:

1. Set billing alerts at $50, $100, $150 in Azure Portal

2. Always stop VMs when not in use: az vm stop

3. Use Spot instances (70% cheaper)

4. Use Azure ML managed compute instead of standalone VMs (auto-scales down to 0)

5. Monitor costs: az consumption usage list -o table

bitsandbytes not working on Mac M1/M2

Cause: bitsandbytes requires CUDA (NVIDIA GPU only).

Fix:

1. Train on Azure ML GPU compute (NC6 with K80), not locally on Mac

2. Or use the QLoRA-free alternative: full LoRA with fp16 on Mac

3. For local Mac testing, use unsloth library which supports MPS

4. Best option: submit all training jobs to Azure ML cloud compute
