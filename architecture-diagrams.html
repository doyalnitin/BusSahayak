3. Voice Booking Flow (Step-by-Step)
1
User Speaks Command
"Mumbai se Delhi do ticket do" — 16kHz audio captured by React Native mic
2
Audio Streamed via WebSocket
Python Async proxy forwards raw PCM frames to Gemini Live API
3
Gemini Processes Audio Natively
Extracts: from=Mumbai, to=Delhi, action=search_buses. No STT→LLM→TTS pipeline.
4
Function Calling → Backend
Gemini calls allocate_seat() → PostgreSQL returns available buses → Redis locks seat for 60 min
5
Audio Response to User
Gemini speaks: "Mumbai se Delhi 3 bus mil gaye. VRL Travels ₹800 mein." — 24kHz PCM audio
4. Why Gemini Live Over Traditional Pipeline
Aspect Traditional (STT → LLM → TTS) BusSahayak (Gemini Live)
Latency 3.5 – 5 seconds < 500ms ✅
Architecture 3 separate API calls 1 WebSocket connection ✅
Barge-in Support No (must wait for TTS to finish) Yes (interrupt anytime) ✅
Audio Quality Variable (depends on TTS engine) 24kHz PCM native ✅
Multilingual Requires separate models Native Hinglish/Hindi/English ✅
Offline Fallback Not available SMS/IVR gateway fallback ✅

7. Security: 60-Minute Tele-Confirmation Engine
Step 1: Voice Booking
User books seat via voice command
Step 2: Redis TTL Lock
Seat locked for 3,600 seconds (60 min)
Step 3: Driver Alert
FCM push to Bus Driver App for confirmation
Step 4: Seat Release
If unconfirmed → Redis expires → seat back to pool
